# v0.3.0 — It can build things, and you can bound what it builds

Read [../ROADMAP.md](../ROADMAP.md) first. This release assumes v0.2.0 shipped.

## Goal

An agent can currently inventory a Nebius account down to the security rule and
then create nothing. `compute_create_instance` is the only create in the
repository; 46 create and 40 update operations out of 305 are reachable by no
tool. This release closes that gap using the schema-driven path — verified
working: `CreateClusterRequest.from_json('{"metadata":{"parent_id":"project-x",
"name":"c1"}}')` produces a populated message, and `get_descriptor()` exposes
`fields_by_name` — so it is one M-sized change plus a describe tool rather than
86 hand-written tools.

In the same release an operator gets a way to bound what the agent may reach.
Adding write coverage without adding a bound is the version of this release no
security team would accept, so the two ship together. The tool surface starts
growing here, so the selector that makes the growth opt-out ships here too.

## Scope

### In

- Generic typed create and update through the catalog.
- A describe tool so a model does not have to guess request bodies.
- Typed managed-Kubernetes create tools and a kubeconfig path.
- A real error taxonomy with retryability and a next action.
- Operation lookup tools, and long-running operations that cannot report false
  success.
- A policy file and a project boundary.
- Toolsets.
- A destructive-operation rate limit.

### Out, deliberately

- Token Factory. v0.4.0. It needs an HTTP client and a second credential axis;
  pairing it with write coverage doubles the untested surface in one release.
- Retries. v0.4.0. `errors.safe(coro)` takes an already-constructed awaitable
  and `nebius.aio.request.Request.__await__` raises
  `RuntimeError('cannot await the finished coroutine')` on re-await, so retry
  is impossible until the call path is rewritten at all 46 sites. The error
  taxonomy here sets the `retryable` flag; nothing acts on it yet.
- Live integration tests. v0.4.0.
- Composite deploy tools. v1.0.0; they need idempotency keys and live rollback
  assertions.
- MCP elicitation. v1.0.0.
- 100% coverage enforcement. v1.0.0; this release makes it reachable, that one
  makes it mandatory.

## Tasks

### v0.3.0-T1 — `nebius_resource_create` and `nebius_resource_update` (M)

The single highest-leverage change available: it turns an inspection tool into
an infrastructure tool.

Acceptance:

1. Both registered in `src/nebius_mcp/tools/generic.py`; `list_tools()` returns
   60, up from 57, once T2 also lands.
2. Requests are built through `catalog.request_class(key, verb)` then
   `RequestCls.from_json(body_json)`.
3. `require_write()` is called **before** verb validation, matching the existing
   ordering in `nebius_resource_delete`, and a read-mode server returns a
   byte-identical error for a supported and an unsupported `resource_type` —
   asserted in `tests/unit/test_tools_generic.py` so the server is not an
   operation-existence oracle.
4. Both route through `preview_or_execute` (dry run to confirm token) and
   `maybe_wait(wait=, timeout_seconds=)`.
5. An unknown JSON field raises `ToolError` naming the field. It is never
   silently dropped — asserted.
6. A parametrized test asserts every `catalog.RESOURCES` key exposing `create`
   can build its request class from `{}` without raising.
7. `ruff`, `ruff format`, `mypy src --strict` stay clean.

Files: `src/nebius_mcp/tools/generic.py`, `src/nebius_mcp/catalog.py`,
`tests/unit/test_tools_generic.py`.

### v0.3.0-T2 — `nebius_describe_operation` (M)

A generic create is unusable if the model has to guess the body. Learning that
`CreateClusterRequest` needs `metadata.parent_id` plus
`spec.control_plane.subnet_id` is currently trial and error against a live API,
where every wrong guess costs a round trip and returns an opaque gRPC error.

Acceptance:

1. `nebius_describe_operation(resource_type, verb, depth=3)` returns
   `{resource_type, verb, request_message, fields: [{name, type, repeated,
   required, enum_values?, nested?}]}` built from
   `catalog.request_class(...).get_descriptor().fields_by_name`. The installed
   `nebius` 0.4.4 descriptor exposes `fields_by_name`, `nested_types_by_name`,
   `enum_types_by_name` and `oneofs_by_name`.
2. Nested messages expand to `depth`; enums list allowed value names.
3. A unit test asserts `nebius_describe_operation('mk8s.cluster', 'create')`
   output contains `metadata.parent_id`, `metadata.name` and
   `spec.control_plane`.
4. A parametrized test walks every `(key, verb)` pair from `catalog.verbs(key)`
   — 305 of them — and asserts none raises.
5. Output passes through `sanitize.wrap()`.

Files: `src/nebius_mcp/tools/generic.py`, `tests/unit/test_describe.py`.

### v0.3.0-T3 — Typed `k8s_create_cluster` and `k8s_create_node_group` (M)

Managed Kubernetes is the flagship workload and deserves resource-shaped
arguments and version validation. The server's own hashed manifest already
advertised `k8s_create_cluster` before v0.2.0-T3 removed the reference.

Acceptance:

1. Both registered with typed arguments mirroring `compute_create_instance`
   (`src/nebius_mcp/tools/compute.py:373-541`): `name`, `parent_id`,
   `subnet_id`, `control_plane_version`, and for node groups `preset`,
   `platform`, `node_count`, `gpu_cluster_id`, `boot_disk_size_gib`.
2. `control_plane_version` is validated against
   `ListClusterControlPlaneVersionsRequest` output **before** any create RPC.
   An invalid version returns `ToolError` listing the valid versions with zero
   create calls made, asserted with a stub that records call count.
3. Both route through `preview_or_execute` and `maybe_wait`.
4. `tests/unit/test_manifest.py::test_no_dangling_tool_references` enumerates
   every registered tool description, extracts substrings matching
   `(compute|k8s|vpc|ai|iam|registry|secrets|nebius|ops)_[a-z_]+`, and asserts
   each is a registered tool name. This complements the v0.2.0 docs gate by
   enforcing the rule inside the manifest itself.

Files: `src/nebius_mcp/tools/k8s.py`, `tests/unit/test_tools_k8s.py`,
`tests/unit/test_manifest.py`.

### v0.3.0-T4 — `k8s_get_kubeconfig` (M)

mk8s users get cluster metadata and a dead end today: the server can list
clusters but cannot hand the agent the one artifact needed to use one, so every
Kubernetes workflow drops out to the `nebius` CLI mid-conversation.

Acceptance:

1. `k8s_get_kubeconfig(cluster_id, context_name=None)` added to
   `src/nebius_mcp/tools/k8s.py`, returning kubeconfig YAML synthesized from
   `ClusterServiceClient.get()`. The SDK has no credentials RPC — verified,
   `ClusterServiceClient` exposes exactly create, delete, get, get_by_name,
   list, list_control_plane_versions, update.
2. Only the exec form is emitted: `users[0].exec.command == "nebius"` with
   arguments that produce a fresh IAM token, so no secret is ever in the
   payload.
3. A unit test with a stubbed client asserts `yaml.safe_load()` parses the
   output and `clusters[0].cluster.server` equals the cluster's public
   control-plane endpoint.
4. A second test asserts `sanitize.redact(kubeconfig_string)` is byte-identical
   to the input, proving no credential leaked.
5. No `subprocess` import is added anywhere under `src/`.
6. The README gains a copy-pasteable snippet ending in
   `kubectl --kubeconfig ~/.kube/nebius.yaml get nodes`.

Files: `src/nebius_mcp/tools/k8s.py`, `tests/unit/test_tools_k8s.py`,
`README.md`.

### v0.3.0-T5 — Error taxonomy with codes, retryability and a next step (M)

`errors.to_tool_error` returns `NebiusAPIError (<ClassName>): <str>` for
everything, so the model cannot distinguish an expired token from a missing IAM
role from a tenant ID passed where a project ID belonged — the three failures a
newcomer actually hits. It retries what will never succeed and abandons what
would have.

Acceptance:

1. gRPC status maps to a closed set: `NEBIUS_NOT_FOUND`,
   `NEBIUS_PERMISSION_DENIED`, `NEBIUS_UNAUTHENTICATED`,
   `NEBIUS_INVALID_ARGUMENT`, `NEBIUS_ALREADY_EXISTS`,
   `NEBIUS_RESOURCE_EXHAUSTED`, `NEBIUS_UNAVAILABLE`,
   `NEBIUS_DEADLINE_EXCEEDED`, `NEBIUS_FAILED_PRECONDITION`, `NEBIUS_INTERNAL`,
   `NEBIUS_UNKNOWN`, `AUTH_ERROR`.
2. Every message begins with the code and carries `retryable` true or false and
   a one-line `next_action`.
3. Specific remedies, asserted by substring:
   `UNAUTHENTICATED` names `nebius iam login` or refreshing
   `NEBIUS_IAM_TOKEN`; `PERMISSION_DENIED` names the resource and the role;
   `NOT_FOUND` where the supplied ID starts `tenant-` says it is a tenant ID and
   to call `iam_list_projects`; `INVALID_ARGUMENT` echoes the offending field;
   `DEADLINE_EXCEEDED` and `UNAVAILABLE` say transient and safe to retry.
4. `confirm.require_write`'s message names the client configuration remedy —
   add `"NEBIUS_MCP_MODE": "write"` to the `env` block and restart the client —
   because in a GUI client there is no shell to export a variable in.
5. `tests/unit/test_errors.py` covers all 12 codes with synthetic status
   fixtures.
6. The redaction added in v0.2.0-T6 still applies to every mapped message,
   asserted by a JWT test.

Files: `src/nebius_mcp/errors.py`, `src/nebius_mcp/confirm.py`,
`tests/unit/test_errors.py`.

### v0.3.0-T6 — Operation tools, and no false success (S)

`operation.maybe_wait` returns `{done: true, successful: false}` inside a normal
success envelope, so a failed delete reads to the model as having worked. All
`maybe_wait` call sites — `compute.py:210,233,272,307,541`,
`_ops_helpers.py:101,134`, `generic.py:314,369` — call it outside `safe()`, so a
wait timeout escapes as an unmapped exception. Separately, every mutation tool
advertises `wait=False` and returns an `operation_id` that no tool can look up.

Acceptance:

1. `maybe_wait` raises `NEBIUS_OPERATION_FAILED`, carrying `operation_id`,
   `status` and `description`, when done and not successful.
2. It wraps its own await, so a timeout raises `NEBIUS_OPERATION_TIMEOUT`
   carrying `operation_id` and a next action naming the poll tool, and reports
   `timed_out: true` in the summary rather than a bare exception.
3. `grep -rn 'maybe_wait(' src/nebius_mcp/tools/` shows no call site outside the
   error mapper.
4. `nebius_operation_get(id)` and `nebius_operation_wait(id, timeout_seconds)`
   registered in `src/nebius_mcp/tools/ops.py`, backed by
   `OperationServiceClient`, returning the `maybe_wait` summary shape plus
   `resource_id`.
5. Every `wait` and `timeout_seconds` field description across `compute.py`,
   `k8s.py`, `ai.py`, `vpc.py`, `registry.py`, `generic.py` and
   `_ops_helpers.py` names `nebius_operation_get`.
6. `tests/unit/test_operation.py` covers success, done-but-failed, timeout, and
   an operation missing the expected attributes.

Files: `src/nebius_mcp/operation.py`, `src/nebius_mcp/tools/ops.py`, all tool
modules, `tests/unit/test_operation.py`.

### v0.3.0-T7 — Policy file and project boundary pinning (L)

`NEBIUS_MCP_MODE=write` is one boolean unlocking 46 delete verbs across 59
resource types plus 8 lifecycle actions. No security team signs off on "the
agent can delete anything the token can reach." Separately, `parent_id` is a
free-form parameter on every list and get tool and on all generic tools, so an
injected instruction supplying a different project reaches it if the credential
can.

Acceptance:

1. New `src/nebius_mcp/policy.py`. `NEBIUS_MCP_POLICY=/path/policy.yaml` with
   `allow` and `deny` glob lists over tool names and over `resource_type` keys.
   Deny by default for any write verb.
2. Enforced in a FastMCP middleware at the same choke point as
   `audit.make_middleware`, so no tool can forget the check, and additionally
   inside `confirm.require_write`.
3. Denied tools are filtered out of `list_tools()`. Verified by loading a policy
   of `allow: [compute_*, ops_*]` and asserting the tool count drops and
   `k8s_delete_cluster` is absent.
4. `nebius_resource_delete(resource_type='iam.service_account', ...)` raises
   `PolicyDenied` even with `NEBIUS_MCP_MODE=write` and a valid confirm token.
5. Every denial emits an audit line naming the matched rule.
6. `policy.example.yaml` ships with a read-only-plus-compute-lifecycle profile.
7. `NEBIUS_MCP_ALLOWED_PARENTS=project-a,project-b`: when set, any tool
   receiving an out-of-list `parent_id` raises before any SDK call. Covers the
   typed tools, `nebius_resource_list`, `nebius_resource_get_by_name` and the
   profile-derived fallback in `_profile_parent_id()`.
8. `nebius_resource_get` and `nebius_resource_delete` take a bare `id` with no
   parent. Either resolve the parent with a `get` first, or state explicitly in
   `SECURITY.md` that ID-addressed calls are outside the boundary. Do not leave
   it undocumented.
9. Unset preserves current behaviour exactly. `check_environment` reports the
   active policy path and boundary.

Files: `src/nebius_mcp/policy.py`, `src/nebius_mcp/server.py`,
`src/nebius_mcp/confirm.py`, `src/nebius_mcp/tools/generic.py`,
`src/nebius_mcp/tools/ops.py`, `policy.example.yaml`,
`tests/unit/test_policy.py`, `SECURITY.md`.

### v0.3.0-T8 — Toolsets (M)

The 57 tools serialize to roughly 46 kB of schema injected into every request,
of which the five generic tools account for a large share because the 59-value
`resource_type` enum repeats in each. A user who only lists VMs pays for KMS,
DNS and MSP on every message. This release adds tools, so the opt-out ships
with them.

Acceptance:

1. `NEBIUS_MCP_TOOLSETS` and `--toolsets` accept a comma list from
   `{ops, iam, compute, k8s, ai, vpc, registry, secrets, generic}`;
   `ops` + `iam` + `generic` form an always-on `core`.
2. `NEBIUS_MCP_TOOLSETS=core` registers 12 or fewer tools, and a test asserts
   the serialized manifest for that set is under 15,000 characters. Record the
   measured full-surface size in the same test so a regression is visible.
3. An invalid name refuses to start with a message listing the valid names,
   exit 2.
4. `nebius-mcp --list-tools [--toolsets ...]` prints name, one-line description
   and annotation flags, exit 0.
5. Unset registers everything, with no behaviour change for existing users.
6. The README states that `get_manifest`'s sha256 is toolset-dependent, since
   pinning it is an advertised feature.

Files: `src/nebius_mcp/server.py`, all tool modules' `register()`,
`tests/unit/test_toolsets.py`, `README.md`.

### v0.3.0-T9 — Destructive rate limit and ticket cap (S)

The realistic worst case is not one wrong delete; it is an injected loop
deleting 200 resources before anyone notices. Nothing slows that down today,
because the model can mint unlimited confirm tokens and `confirm._active` grows
without bound.

Acceptance:

1. `NEBIUS_MCP_MAX_DESTRUCTIVE_PER_SESSION`, default 5, counted in
   `src/nebius_mcp/confirm.py` across every path reaching a delete or an
   irreversible action.
2. The N+1th destructive call raises regardless of a valid confirm token, and
   the refusal is audit-logged with `decision: denied, reason: rate_limit`.
3. The counter resets only on process restart.
4. A test issues six valid confirm cycles and asserts the sixth SDK call never
   happens.
5. `confirm._active` gains a size cap so token minting cannot grow memory
   without limit.

Files: `src/nebius_mcp/confirm.py`, `tests/unit/test_confirm.py`,
`tests/unit/test_destructive_flow.py`.

## Risks

- **Generic create is a large blast-radius feature with no live test.** Nothing
  in this release runs against a real API; that is v0.4.0. Mitigate by keeping
  every create behind `preview_or_execute` and by the parametrized
  request-construction test, and by not shipping composite multi-step creates
  until v1.0.0.
- **`from_json` strictness is assumed, not verified across all 46 create
  types.** The acceptance test constructs from `{}` for every type; if some type
  rejects an empty body, record the exception list in the plan rather than
  loosening the test.
- **Policy filtering changes `list_tools()` and therefore the manifest hash per
  configuration.** This must be documented, or users pinning the hash will see
  spurious tamper signals. T8 acceptance item 6 covers it.
- **`_ID_PATTERNS` remains inferred.** If v0.2.0-T3 wired `validate_id` in, a
  stricter-than-reality pattern will reject valid IDs on the new create path.
  Prefer rejecting only on shapes confirmed against the API.
- **T7 is the largest item here and touches the same files as T1 and T6.**
  Sequence T1, T2, T5, T6 before T7.

## Definition of done

- `list_tools()` returns the expected count with all toolsets enabled, and the
  new count is recorded in `CHANGELOG.md` alongside the new manifest sha256.
- Every catalog resource exposing `create` builds its request class from `{}`
  without raising.
- A read-mode server returns byte-identical errors for supported and
  unsupported resource types, proven by test.
- A policy of `allow: [compute_*, ops_*]` measurably reduces `list_tools()` and
  blocks `nebius_resource_delete` on an IAM service account in write mode with a
  valid confirm token.
- `NEBIUS_MCP_TOOLSETS=core` produces a manifest under 15,000 characters.
- `grep -rn 'maybe_wait(' src/nebius_mcp/tools/` shows no unwrapped call site.
- `ruff`, `ruff format`, `mypy src`, `pytest tests/unit`,
  `scripts/check_docs.py` and `scripts/check_docs_links.py` are green.
