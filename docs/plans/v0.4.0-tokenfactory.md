# v0.4.0 Token Factory — the second plane, scoped by what the API actually is

Read [../ROADMAP.md](../ROADMAP.md) first, then [v0.4.0.md](v0.4.0.md). This
document **refines tasks T3–T6 of that plan**; it does not replace it. T1, T2
and T7–T11 stand as written and this document depends on two of them.

**This release assumes v0.3.0 shipped.** That sentence is copied from
[v0.4.0.md](v0.4.0.md), and it is load-bearing here — see
[Sequencing](#sequencing), which is the part of this plan most likely to be
skipped and least safe to skip.

## Why this document exists

[v0.4.0.md](v0.4.0.md) was written before anyone had read the Token Factory
API. It says so: [README.md](README.md) lists "Token Factory endpoint paths,
whether Data Lab has a public REST surface" among the facts "nobody in this
project has verified", and instructs that such tasks "begin with a discovery
step and treat a documented negative result as a valid outcome."

That discovery step has now run. It changed enough that writing it into the
existing task descriptions would have hidden the changes, so it is a separate
document that names each correction explicitly.

## What is now verified

Everything in this section was read from a machine-readable artifact or
reproduced by execution. Anything that was not is in
[Unknowns](#unknowns-and-what-would-settle-each).

**Token Factory publishes a complete, public, unauthenticated OpenAPI 3.1
document** at `https://api.tokenfactory.nebius.com/openapi.json` —
`info.version` `"20260729-026192a63"`, 37 paths, 47 operations, 368 schemas. No
credentials are needed to read it.

This is the single most consequential finding, because
[v0.4.0.md](v0.4.0.md)'s T6 requires that "every endpoint path is confirmed
against a live tenant". Paths do not need a tenant. Behaviour, quotas, model
ids and entitlement still do.

| Area | Operations | Notes |
|---|---|---|
| Data Lab | **20** | 8 dataset, 6 multipart upload, 6 operation engine |
| Fine-tuning | 9 | includes the two checkpoint endpoints T6 omits |
| Inference | 7 | chat, completions, embeddings, rerank, responses, images |
| Files | 6 | includes `content` and `link`, both excluded below |
| Dedicated endpoints | 5 | on `/v0/`, not `/v1/` |

- **Base URL**: `https://api.tokenfactory.nebius.com`, documented with the
  version path as `.../v1/`. One `servers[]` entry, no variables.
- **Auth**: a single `HTTPBearer` scheme — `Authorization: Bearer <key>`. No
  per-operation override.
- **OpenAI compatibility is real**: 22 of `ChatCompletionRequest`'s 23
  properties are OpenAI-standard; the 23rd is `extra_body`.
- **Two legacy hosts are live**, not dead: `api.studio.nebius.com` *and*
  `api.studio.nebius.ai` both answer `/v1/models` with an identical 401 and no
  redirect. T4's acceptance test names only the first.

### The two roadmap unknowns, settled

**Data Lab has a public REST API.** 20 of 47 operations, the largest single
area in the product. It reads as console-only from outside because the Data Lab
narrative pages are UI-only and never link `api-reference/datasets/`.

**There is no OpenAI-style Batch API.** Zero of 37 paths match `batch`. Batch
inference is an `OperationType` on `POST /v1/operations`, so
[v1.0.0.md](v1.0.0.md) item 5's "batch" and "Data Lab" are one piece of work,
not two.

## Corrections to the existing plan

Each of these is a change to a task in [v0.4.0.md](v0.4.0.md) or
[v2.0.0.md](v2.0.0.md). They are listed separately from the tasks below so a
reviewer can check them without reading the whole document.

1. **T3's `NEBIUS_API_KEY` fallback is a hazard, not merely a guess.** Nebius's
   own Sandboxes documentation uses that same variable name for an *IAM* token.
   A blind second-precedence fallback would send a credential that can delete
   production infrastructure to an inference endpoint. Keep
   `NEBIUS_TOKEN_FACTORY_API_KEY` first — it appears nowhere upstream, which is
   exactly what makes it unambiguous — and require the fallback to reject a
   value that parses as a JWT or matches the `ne1…` IAM shape.

2. **T4 discards the catalog's most useful fields.** `GET /v1/models?verbose=true`
   returns `RichModel`, whose *required* fields include `pricing` and
   `context_length`, plus `status`/`status_reason` and `regions`. T4 as written
   returns `{id, owned_by}`.

3. **T6's nine-tool list cannot collect a fine-tune's output.** It omits
   `GET /v1/fine_tuning/jobs/{id}/checkpoints` and `.../checkpoints/{cid}`.
   `FineTuningCheckpoint.fine_tuned_model_checkpoint` is the id passed back to
   chat completion, so without those two the surface starts and watches a job
   and then cannot use the result.

4. **T6 gates the wrong operation.** It puts `delete_file` and
   `cancel_fine_tuning_job` behind the confirm token and leaves *create*
   ungated. Cancel **stops** spend; create **commits** it.

5. **T5 specifies `readOnlyHint: True` for `tokenfactory_chat_completion`.**
   That is wrong for the reason this repo already reasoned through for
   `secrets_reveal_payload`: `readOnlyHint` and `destructiveHint` are the two
   fields clients read when deciding what to auto-approve, and a billable tool
   must not look free.

6. **T4's legacy-host test is incomplete** — see `api.studio.nebius.ai` above.

7. **v2.0.0 item 6 (Sandboxes) should be deleted, not deferred.** Nebius ships
   `contree-mcp` (0.3.0 on PyPI, 17 tools, plus a CLI and a Python SDK).

8. **v1.0.0 item 5's "batch"** collapses into Data Lab; there is no batch API.

## Scope

### In

- One credential axis for the inference plane, with plane-isolation checks.
- A read surface: model catalog with pricing, fine-tuning job/event/checkpoint
  reads, file list/get.
- `tokenfactory_chat_completion`, behind a spend gate that does not exist yet.
- Fine-tuning create and cancel, and file upload and delete.
- Five new tools.

### Out, deliberately

- **Sandboxes, in any release.** Nebius ships `contree-mcp` first-party. The
  README should point at it. Beyond duplication: a `sandbox_exec` tool would
  let an injection carried in a resource name — the channel `SECURITY.md`'s
  first threat row concedes is only *partially* mitigated — reach arbitrary
  code execution.
- **`POST /v0/dedicated_endpoints`.** Provisions GPUs and bills continuously
  until deleted. It is the one cost shape no per-call fuse bounds, cancelling
  recovers nothing, and it is on an unstable `/v0/` contract. `ai_endpoint_*`
  already covers the managed-endpoint case on the IAM plane.
- **The `yql` operation type**, now and as a passthrough later.
  `YQLParams.query` is a free-text query executed against the user's datasets.
- **Data Lab.** 20 of 47 operations is a release of its own, not a phase of
  this one.
- **`GET /v1/files/{id}/content` and `/link`.** File content is raw
  user-uploaded bytes — a training corpus is precisely the attacker-authored
  blob that should not enter agent context, and it defeats any response cap.
- **Embeddings, images, rerank, legacy `/v1/completions`, `/v1/responses`.**
  None appears in a traced session. A float array has no consumer in model
  context, and all are billable.
- **Streaming.** A client-side scope cut, not an API limitation — `stream` and
  `stream_options` exist on the request schema. Tool descriptions must say
  which it is.
- **The `openai` package as the HTTP client**, despite it being what every
  official Nebius example uses — but see risk R4, because the stated reason is
  weaker than it looks.

## Sequencing

**This work is third in line, not first.** Two things come before it, and the
temptation to skip both is the main risk in this document.

1. **PyPI registration** ([v0.2.0.md](v0.2.0.md) T1/T2). Still open: `git tag -l`
   is empty and `pyproject.toml` reads `version = "0.1.0"`. The argument is
   arithmetic — the real-world call count of any tool shipped into an
   uninstallable package is zero.

2. **v0.3.0, all nine items.** [v0.4.0.md](v0.4.0.md) line 3 says "This release
   assumes v0.3.0 shipped", and [README.md](README.md) says not to start a
   v0.4.0 item while v0.3.0 items are open. v0.3.0 closes the largest gap in
   the repository: 46 create and 40 update operations are unreachable. A second
   *plane* while the first plane cannot create anything is the wrong order, and
   nothing in the discovery above changes that.

3. **v0.4.0-T1**, the integration harness. TF4, TF6 and TF7 below have
   acceptance criteria that assume `requires_token_factory` exists.
   `tests/integration/` currently contains one 0-byte `__init__.py` and CI runs
   `pytest tests/unit` explicitly. T1 is a prerequisite, not a parallel track.

On cutting: [v0.4.0.md](v0.4.0.md) says it "can be cut after task 9 … tasks 10
and 11 are independent." That means keep T1–T9 — which *includes* Token Factory
— and drop T10 and T11. It is not licence to drop this work; if this work is
cut, that needs its own justification.

## Tasks

Sized on the scale in [README.md](README.md): S under a day, M one to three
days, L a week or more.

### v0.4.0-TF1 — Sanitizer fixes, before any HTTP code exists (S)

Three defects, all reproduced by executing the repo's own functions. They are
first because they are testable against the current tree with no Token Factory
code and no credentials.

- `api_key` normalizes to `apikey`, which is not a substring of `secret`,
  `token`, `password` or `credential` — so a field with that name is returned
  verbatim in every spelling. Token Factory's fine-tuning request carries
  `WandbConfigRequest.api_key`, but the gap is not Token Factory-specific.
- `cached_tokens`, `reasoning_tokens`, `completion_tokens_details` and
  `prompt_tokens_details` are redacted by the `token` substring, while the four
  classic counters pass only because they are already on the benign list.
- The Token Factory API key has **strictly weaker sanitizer coverage than the
  IAM credential**, and this must be stated rather than fixed by guesswork. An
  IAM token is caught by two *value* patterns — the `eyJ…` JWT rule and
  `\bne1[a-z0-9]{30,}` — which run on both the success and error paths. No
  value pattern recognises a Token Factory key. Ship the field-name rules now;
  a value regex invented from the docs' `ABC123...` placeholder would match
  nothing while reading in review as coverage.

**Acceptance.** `redact({"api_key": x})` returns `<redacted>` for `api_key`,
`apiKey`, `api-key`, `API_KEY`, `wandb_api_key`. The four usage fields round-trip
unchanged. Removing the new substring fails a named test. `SECURITY.md` gains a
row stating the coverage asymmetry, not merely the expiry difference.

> Status: shipped ahead of this plan in the sanitizer work that found it.

### v0.4.0-TF2 — Credential axis and HTTP client lifecycle (M)

Refines T3 and T4. **Zero new tools.**

Run the IAM-token experiment **first** and record the result with its date: one
`curl` against `/v1/models` with a Nebius IAM access token. A 200 deletes most
of this task.

- `httpx>=0.28,<1` becomes a declared dependency. This is a promotion, not an
  addition: `fastmcp` 3.2.4 already requires `httpx<1.0,>=0.28.1`. Zero new
  wheels.
- New `src/nebius_mcp/http.py`: `async_client(base_url)` keyed by base-URL
  **string**. It cannot reuse `client.py`'s `service()`, which is keyed by
  class. Plus `reset_http_clients()` that awaits `aclose()`.
  - Blocker the roadmap does not name: `reset_clients()` is synchronous and is
    called from `auth.reset_sdk()`. Closing an `httpx.AsyncClient` requires an
    await. Resolve this deliberately — do not leak the connection pool.
- `auth.resolve_token_factory_credentials()` reads
  `NEBIUS_TOKEN_FACTORY_API_KEY`, then `NEBIUS_API_KEY` **only if the value
  does not parse as a JWT and does not match the `ne1…` IAM shape**, then the
  profile.
- A fourth field the roadmap omits: `ai_project_id`, an optional query
  parameter on 22 of 47 operations. **Resolved from environment and profile
  only — never a tool argument.** Whether one key can reach sibling projects is
  unknown, and a model-settable project id would let an injection redirect
  reads and, later, billable calls.
- `check_environment` gains a `token_factory` sub-model: `api_key_present`,
  `source`, `base_url`, `ai_project_id`. No separate `resolve_base_url` tool —
  it is a diagnostic, and `next_steps` already exists.
- Vendor the OpenAPI document as `tests/golden/tokenfactory-openapi.json` and
  add a **scheduled workflow** that re-fetches it, diffs, and opens an issue on
  change. Without the schedule the fixture only detects the maintainer's own
  typos, which is a self-consistency check sold as a freshness check.

**Acceptance.** A 401 surfaces as a typed error, never an httpx traceback. Both
legacy hosts are forbidden by test. `NEBIUS_API_KEY` holding a JWT is refused
with an error naming the plane confusion. The scheduled drift job runs.

### v0.4.0-TF3 — The read surface (M)

Refines T4 and T6. **Three tools.**

- `tokenfactory_list_models` — `GET /v1/models?verbose=true`, returning `id`,
  `pricing`, `context_length`, `status`, `status_reason`, `regions`,
  `supported_features`. 300s TTL cache cleared by `reset_http_clients()`.
  **Pricing is returned as the raw strings the API sends.** Do not render
  currency and do not multiply — see [Unknowns](#unknowns-and-what-would-settle-each).
- `tokenfactory_job(action, job_id)` — one read dispatcher over five
  operations: list jobs, get job, events, list checkpoints, get checkpoint.
- `tokenfactory_file(action, ...)` — list and get only in this task.

**Acceptance.** The job dispatcher covers all five reads including both
checkpoint endpoints. No tool references `/v1/files/{id}/content` or `/link`. An
integration test skips cleanly without credentials (requires T1).

### v0.4.0-TF4 — The spend gate (M)

**New.** The roadmap has no spend concept, and `NEBIUS_MCP_MODE` cannot express
"costs money but changes nothing".

This task exists before any billable tool because of a collision the plan must
resolve first. `tests/unit/test_write_gate_coverage.py` enumerates every tool
whose `readOnlyHint` is `False`, calls it with `NEBIUS_MCP_MODE` unset, and
asserts the error body contains the literal string `"write mode is disabled"`.
Its docstring calls this the load-bearing safety property. A tool gated on spend
rather than write mode fails that test.

**Generalise the invariant explicitly, in this task, before a billable tool
exists**: every non-read-only tool must refuse when unconfigured, naming exactly
one of a closed set of gates. Do not weaken the test to accommodate a new tool.

- `NEBIUS_MCP_ALLOW_SPEND=1`, unset by default, orthogonal to write mode,
  modelled on the `NEBIUS_MCP_ALLOW_SECRET_REVEAL` precedent.
- A **pre-request clamp**, not only a post-hoc fuse. Reading `usage` off a
  response bounds call *count* and places no bound on the cost of a single call
  in flight — and single-call cost is the dominant shape here, since an agent
  can assemble an enormous prompt from resource descriptions this server
  already reads. Clamp `max_tokens` to a hard limit in the same idiom as
  `pagination.clamp_page_size`, whether or not the caller supplied it.
- A per-process fuse on top, and a `SECURITY.md` known-gap bullet saying
  plainly what it cannot do: it counts calls and tokens, not money; it cannot
  price a token; and two server instances against one key each get a full fuse.

### v0.4.0-TF5 — `tokenfactory_chat_completion` (M)

Refines T5. **One tool**, behind TF4's gate, annotated `readOnlyHint: False`.

Returns `{content, model, usage, finish_reason}` through `sanitize.wrap()`,
with a **tool-local cap that stays permanently** — tighter than T10's eventual
global cap, which is a ceiling rather than a replacement.

The threat row this needs is more specific than "model output is untrusted":
an attacker with write access sets a resource description; the agent reads it
through any of the 57 existing read tools; it reaches the prompt; the completion
comes back as text the same agent acts on. That is a laundering path from
stored injection to generated instruction, inside one server.

### v0.4.0-TF6 — The write path (L)

Refines T6, with the gating inverted.

- `tokenfactory_file` gains `upload` and `delete`. Upload names a **local path
  the operator's environment can reach**, rather than accepting inline content
  from the model — a training corpus is a persistent injection vector that
  survives restarts, and attribution matters.
- `tokenfactory_fine_tune(action='create'|'cancel')`.
  - `create`: write mode **+** `NEBIUS_MCP_ALLOW_TOKENFACTORY_WRITE` **+** spend
    gate **+** confirm token. The extra plane-scoped opt-in exists because
    `is_write_mode()` is one global boolean: enabling write mode to submit a
    fine-tune would otherwise unlock `nebius_resource_delete` across all 46
    delete-capable resource types on the IAM plane.
  - `cancel`: write mode + confirm token, **but not the spend gate**. A gate
    that can stop you halting a bill is the wrong gate.
- The create preview must carry **cost**, and this task therefore depends on
  the pricing-unit question being answered in TF3. A preview that says
  "pricing: 0.13" before an irreversible, hours-long, continuously-billing
  commitment is safety-useless.

### v0.4.0-TF7 — Documentation, generated not written (S)

- `docs/token-factory-api.md` is **generated from the vendored spec** with a CI
  `git diff --exit-code` check. This repository has a documented, repeated
  failure of hand-maintained facts: `ROADMAP.md` records the test count having
  been wrong at 82, 84, 85, 90, 92 and 94 across four documents. Do not add
  another hand-typed table with hand-typed dates.
- `README.md` gains a Safety-model bullet. After this work, "read-only until
  you opt in" stays *literally* true while becoming misleading: read-only mode
  stops the server changing things, not costing money. `SECURITY.md` alone is
  not where that belongs — the claim is in the README.
- `README.md` "Not covered" points at `contree-mcp` for Sandboxes.
- A test asserting every environment variable named in `SECURITY.md`'s threat
  table is actually read somewhere under `src/`, so no row can describe a gate
  that does not exist.

## Unknowns, and what would settle each

Stated as unknowns, per [README.md](README.md). None of these blocks TF1.

| Unknown | What settles it |
|---|---|
| **Pricing units.** Fields are bare strings defaulting to `"0"`, with no currency and no denominator. Per token? Per million? This is the highest fabrication risk in the plan. | One authenticated `GET /v1/models?verbose=true`. Blocks TF6's cost preview. |
| Whether an IAM token authenticates against Token Factory. Everything points to no — zero occurrences of "IAM" or "tenant" in 265 kB of spec — but it is untested. | One `curl`. A 200 deletes most of TF2. |
| The literal format of a Token Factory API key (prefix, length, charset). Docs show only `ABC123...`. | Minting one key. Blocks any value regex — which is why TF1 ships field-name rules only. |
| Whether a Token Factory key expires. No TTL or rotation policy is documented. | Console or support. Affects the `SECURITY.md` row. |
| Whether `ai_project_id` can reach sibling projects, i.e. whether it is a convenience or a privilege-escalation surface. | One authenticated call with a foreign project id. Until then it stays environment-only. |
| Per-tenant entitlement to fine-tuning and files. The spec proves the surface exists; not that a given tenant may POST to it. | A funded tenant. |
| Whether regional hosts serve only inference or also files/fine-tuning/datasets. Proven: they do not serve `openapi.json`. | Authenticated probes per path. |
| Sandbox egress policy. The Sandboxes MCP security page (retrieved 2026-08-09, HTTP 200) covers vulnerability reporting only and states no egress, uid or TTL policy. | Irrelevant while Sandboxes stays out of scope — which is one more reason it should. |

Two claims from the investigation were **demoted** rather than carried: that
Token Factory organizations are IAM tenants (nothing reachable says so), and an
earlier citation for the sandbox-egress gap that pointed at a page which does
not say it. The conclusions survive; the evidence did not.

## Cost

On this repository's own scale: **roughly 12–31 agent-days for TF2–TF7**, call
it 3–6 agent-weeks. The plan states this because the existing v0.4.0 document
does not state its own total, and this work sits behind v0.3.0's nine items.

Three items are outside that estimate and should be assumed to grow it:
v0.4.0-T1, the synchronous-to-asynchronous ripple in `reset_clients()`, and
obtaining a funded tenant with fine-tuning entitlement.

**Tool budget.** Measured on the current tree: 57 tools, 44,469 canonical
manifest characters, ~11,117 tokens — already past both of the documented lines
(30–50 available tools; 10k tokens of definitions). So no proposal here can be
argued as *crossing* a threshold, only as widening an overage.

Five new tools, estimated against measured reference points rather than the
44,469/57 average — dispatchers with action enums and confirm tokens measure
2,054–2,762 characters each, not 779 — come to roughly **+5,000–7,000
characters, or +11% to +16%**. State the honest number.

Do **not** treat generic-tool budget reclaim as new work: the six `nebius_*`
tools cost 11,063 characters, 24% of the whole surface, and
[v0.3.0.md](v0.3.0.md) T8 (toolsets) already diagnoses this in nearly the same
words and is a strictly better lever than replacing the `resource_type` Literal
with a validated string, because it keeps schema-level validation.

## Risks

**R1 — Sequencing pressure.** This is the interesting work and v0.3.0 is not.
The plan will be skipped ahead of. Mitigation: the dependency is stated in three
documents; treat a PR that opens a TF task while v0.3.0 is open as a plan
change requiring justification in the same PR.

**R2 — The write-gate invariant.** TF4 changes the repository's load-bearing
safety test. Done carelessly this weakens the one property that makes the
server's headline claim checkable. Mitigation: generalise the invariant to a
closed set of named gates, never to "refuses somehow".

**R3 — Pricing fabrication.** Every layer wants to render a number a human can
read. The units are unknown. Mitigation: raw strings until one live call
settles it; TF6 blocks on it.

**R4 — No retry, timeout or rate policy.** T7 (retryable call path) and T9
(rate budget) are not in this document, so the HTTP path would ship without
either — and `POST /v1/chat/completions` against a shared gateway is the most
429-prone call in the product. This also weakens the stated reason for
rejecting the `openai` package, which was that it duplicates machinery this
plan does not build. Resolve before TF5: either schedule a Token Factory-local
subset (timeout, bounded retry on 429/5xx for idempotent GETs only, never on
POST), or revisit the dependency decision.

**R5 — Spec drift.** The vendored fixture is only as fresh as the last fetch.
Mitigation: the scheduled diff job in TF2, which is the part of that task most
likely to be dropped as optional.
