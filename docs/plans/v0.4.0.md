# v0.4.0 — The second plane, and proof that any of it works

Read [../ROADMAP.md](../ROADMAP.md) first. This release assumes v0.3.0 shipped.

## Goal

Two things this project has never had.

First, a live test. Every assertion about Nebius behaviour in this repository is
made against a mock. `tests/integration/` contains only an empty `__init__.py`,
and CI runs `pytest tests/unit` explicitly. The two most serious defects the
project has shipped — the audit log on stdout, and a bare `SDK()` that ignored
`~/.nebius/config.yaml` — both passed a fully green suite, because mocking at
the service-client boundary means `get_sdk` never executes and an in-process
client never opens a pipe.

Second, Token Factory. It is what Nebius sells to AI builders and it is 0%
reachable, for the mundane reason that `pyproject.toml` has no HTTP client and
`auth.py` has no concept of an API key. Every Token Factory capability is
blocked behind that one plumbing change.

Around them, the reliability substrate 57 tools have been sitting on without:
retries, idempotency keys, a rate budget, correct pagination, and a request id
a user can hand to Nebius support.

This is the largest pre-1.0 release. It can be cut after task 9 if the Token
Factory discovery work runs long; tasks 10 and 11 are independent.

## Scope

### In

- A live integration harness, credential-gated, plus a scheduled CI job.
- An HTTP client and a Token Factory credential axis alongside the IAM plane.
- Token Factory inference, embeddings, files and fine-tuning.
- The retryable call path, idempotency keys, a rate budget, correct pagination.
- Request-id propagation, a useful audit record, and a response size cap.
- An SDK contract suite and a nightly dependency canary.

### Out, deliberately

- Token Factory batch, dedicated endpoints and Data Lab. v1.0.0. They depend on
  endpoint paths nobody has verified, and the auth and HTTP plumbing needs one
  release of live exercise first.
- Sandboxes. v2.0.0. It is the sharpest safety surface in the product and lands
  after the confirm, audit and sanitize machinery has been proven across both
  credential planes.
- Composite deploy tools. v1.0.0.
- Any HTTP transport for the MCP server itself. That is a different thing from
  an HTTP client for Token Factory; the transport is v1.0.0 and is blocked on
  session-scoped state.

### v0.4.0-T4 — Model catalog and base-URL resolution (S)

The base-URL problem is Token Factory's documented first onboarding failure:
regional hosts serve subsets of the catalog, so hardcoding a region makes models
silently vanish, and the most common wrong guess returns 401.

Acceptance:

1. The default base URL is the generic superset host, overridable with
   `NEBIUS_TOKEN_FACTORY_BASE_URL`. A regional host is never the default.
2. `tokenfactory_list_models()` returns `{items: [{id, owned_by}], base_url,
   count}` wrapped by `sanitize.wrap()`.
3. Against a live key it returns at least 20 model ids (integration test).
4. `tokenfactory_resolve_base_url(model_id=None)` returns `{recommended,
   regional_hosts, warning}` and warns when the caller supplies a regional
   override, explaining that regional hosts are subsets.
5. A unit test asserts the literal string `api.studio.nebius.com` appears
   nowhere under `src/`.
6. The model list is cached in-process with a 300-second TTL, cleared by
   `reset_http_clients()`.

Unknown: the exact set of regional hosts and the canonical generic host must be
confirmed against a live tenant and recorded with a verification date in
`docs/token-factory-api.md`. Do not guess them from memory.

Files: `src/nebius_mcp/tools/tokenfactory.py`, `docs/token-factory-api.md`,
`tests/unit/test_tokenfactory.py`, `tests/integration/test_tokenfactory.py`.

### v0.4.0-T5 — `tokenfactory_chat_completion` and `tokenfactory_embeddings` (M)

The payload of the milestone: an agent goes from having a Nebius account to

Acceptance:

1. `tokenfactory_chat_completion(model, messages, max_tokens=2048,

6. Both tools set `readOnlyHint: True` and `openWorldHint: True`.
7. Unit tests use a mocked httpx transport; the integration test skips unless a
   Token Factory key is present.

Files: `src/nebius_mcp/tools/tokenfactory.py`, `tests/unit/test_tokenfactory.py`,

### v0.4.0-T7 — Retryable call path (M)

An architectural blocker, not a nice-to-have. `errors.safe(coro)` takes an
already-constructed awaitable, and `nebius.aio.request.Request.__await__`
raises `RuntimeError('cannot await the finished coroutine')` on re-await, so
retry is literally impossible in the current shape at all 46 call sites.
Separately, the SDK accepts `retries`, `timeout`, `per_retry_timeout` and
`wait_for_ready`; this repository passes none of them, so every tool inherits
defaults nobody chose.

Acceptance:

1. `errors.safe_call(factory: Callable[[], Awaitable[T]], *, idempotent: bool,
   timeout: float | None)` replaces `safe`. `grep -rn 'await safe(' src/`
   returns 0, down from 46.
2. Retries only on `NEBIUS_UNAVAILABLE`, `NEBIUS_DEADLINE_EXCEEDED`,
   `NEBIUS_RESOURCE_EXHAUSTED`, `NEBIUS_INTERNAL`, and only when
   `idempotent=True`. Maximum three attempts, full-jitter backoff, at most 8
   seconds of added latency.
3. `NEBIUS_MCP_TIMEOUT_SECONDS`, `NEBIUS_MCP_RETRIES`,
   `NEBIUS_MCP_PER_RETRY_TIMEOUT` overrides, reported by `check_environment`.
4. `tests/unit/test_retry.py` drives a fake client and asserts attempt counts
   per status code, and that create, delete and action verbs make exactly one
   attempt.

Files: `src/nebius_mcp/errors.py`, `src/nebius_mcp/client.py`, all tool
modules, `tests/unit/test_retry.py`.

### v0.4.0-T8 — Idempotency keys on every mutation (S)

The confirm token stops a model from double-deleting; it does nothing about a
transport retry double-creating a GPU instance. Once T7 lands, a retried create
without an idempotency key bills the user twice. The SDK supports this in
`nebius/aio/idempotency.py`.

Acceptance:

1. Every create, delete and lifecycle-action request sets a deterministic key
   of `sha256(tool_name + canonical_json(args) + confirm_token)[:32]` through
   the SDK metadata path.
2. `tests/unit/test_idempotency.py` asserts the key is stable across two
   identical calls and differs when any argument changes.
3. An integration test issues the same create twice with the same key and
   asserts exactly one resource exists afterwards.

Files: `src/nebius_mcp/client.py`, `src/nebius_mcp/confirm.py`, tool modules,
`tests/unit/test_idempotency.py`, `tests/integration/`.

### v0.4.0-T9 — Rate budget and pagination correctness (M)

`grep -rn 'rate\|429\|RESOURCE_EXHAUSTED\|throttle' src/` returns nothing. An
agent that calls `nebius_list_resource_types` then fans out across every
list-capable type can get the whole account throttled — a failure the user
experiences in their other tooling, not just here.

Three verified pagination bugs in `src/nebius_mcp/tools/generic.py`: line 197,
`if page_token and 'page_token' in fields` silently discards the caller's token
when a resource's list request lacks the field, so a paginating agent loops
forever on page one; line 199 does the same for `filter`, so a model that asked
for a filtered set acts on an unfiltered one; line 204 reads only
`getattr(resp, 'items', None)`, so a response using a different repeated field
name yields an empty list indistinguishable from "you have no resources".

Acceptance:

1. A token-bucket limiter in `client.py`: default 10 requests per second and 5
   concurrent in-flight calls, tunable with `NEBIUS_MCP_MAX_RPS` and
   `NEBIUS_MCP_MAX_CONCURRENCY`. A `NEBIUS_RESOURCE_EXHAUSTED` response halves
   the bucket for 30 seconds and then recovers. The audit record gains
   `throttled_ms`.
2. `tests/unit/test_rate_limit.py` fires 100 concurrent calls at a fake client
   that records maximum observed concurrency and asserts it never exceeds the
   cap.
3. An unsupported `page_token` or `filter` raises `NEBIUS_INVALID_ARGUMENT`
   naming the resource type and the supported request fields, instead of being
   ignored.
4. Every list response echoes `applied: {page_size, page_token: bool, filter:
   bool}`.
5. `tests/unit/test_pagination_contract.py` enumerates every list-capable
   resource in `catalog.RESOURCES`, resolves each list method's response
   message through the same `_resolve_alias` path, and asserts it exposes both
   `items` and `next_page_token`, so an SDK rename fails CI loudly.
6. An integration test paginates `compute.disk` with `page_size=1` across at
   least three pages, asserting no repeated IDs and a terminating token.

Files: `src/nebius_mcp/client.py`, `src/nebius_mcp/pagination.py`,
`src/nebius_mcp/tools/generic.py`, `tests/unit/test_rate_limit.py`,
`tests/unit/test_pagination_contract.py`.

### v0.4.0-T10 — Correlatable, redacted, size-bounded observability (M)

`audit.log_call` records `sha256(args)[:16]`, so an incident reviewer learns
that `compute_delete_instance` ran but not which instance. Nebius support's
first question is the request id, and the SDK's `Request` object exposes
`request_id`, `trace_id`, `status` and `trailing_metadata` — all discarded at
every call site. Separately, `sanitize.py`'s module docstring claims "We also
cap response sizes"; no cap exists in the file.

Acceptance:

1. The call helper retains the `Request` object and captures `request_id` and
   `trace_id` on both success and failure. Absence degrades to null rather than
   raising.
2. Every `NEBIUS_*` error message ends with `request_id=<id> trace_id=<id>`.
3. Audit records gain `request_id`, `trace_id`, `duration_ms`, `error_code`,
   `resource_id`, `result_bytes`, `items_returned`, `attempt_count`,
   `throttled_ms`, `session_id`, `principal` and `decision` in
   `{allowed, denied, preview_issued, confirmed}`.
4. `NEBIUS_MCP_AUDIT_ARGS=hash|redacted|full`, default `redacted`, records
   resource and parent ids with `sanitize.redact()` applied. A test runs a
   delete of a known instance id and asserts that exact id appears in the log
   line, and separately that a JWT passed as an argument appears as
   `<redacted>`.
5. `NEBIUS_MCP_AUDIT_FILE` writes JSON lines, file created mode 0600, rotation
   documented. `docs/audit-schema.md` documents every field.
6. `sanitize.wrap` enforces `NEBIUS_MCP_MAX_RESPONSE_BYTES`, default 256 KiB,
   truncating the items array and setting `truncated: true`, `truncated_at` and
   a next action naming `page_token`.
7. `NEBIUS_MCP_LOG_FORMAT=json|text` and `NEBIUS_MCP_LOG_FILE` added, so stdio
   users can read logs at all.

Files: `src/nebius_mcp/audit.py`, `src/nebius_mcp/errors.py`,
`src/nebius_mcp/sanitize.py`, `docs/audit-schema.md`,
`tests/unit/test_audit_stream.py`.

### v0.4.0-T11 — SDK contract suite and a nightly dependency canary (M)

`catalog.request_class` resolves generated `_NebiusType_<proto_path>_<8hex>`
aliases by regex-parsing a module path. A patch bump inside `nebius>=0.4.4,<0.5`
that changes that scheme silently drops verbs, and tools begin answering "does
not support delete in nebius SDK 0.4.x" — a plausible-sounding lie the model
relays to the user as fact. Separately, dependencies allow `nebius<0.5` and
`fastmcp<4`, so a release published overnight can break every user with zero
commits here.

Acceptance:

1. `tests/unit/test_sdk_contract.py` asserts, for all 59 resources: the client
   class imports; the derived verb histogram matches
   `tests/golden/catalog_verbs.json` — list 57, get 55, create 46, delete 46,
   update 40, get_by_name 33, undelete 5, start 4, stop 4, activate 3,
   deactivate 3, restart 2, cancel 2, resume 1, upgrade 1, purge 1, issue 1,
   revoke 1, total 305; `_resolve_alias` succeeds for every verb without
   falling back, with fallback usage asserted at zero; and
   `sanitize.proto_to_dict` round-trips one live message per domain.
2. A new `sdk-matrix` CI job installs `nebius==0.4.4` and the highest resolvable
   version under 0.5 and runs the suite, printing the golden diff on mismatch.
3. `.github/workflows/nightly.yml` runs `uv lock --upgrade` then the unit,
   stdio-conformance, sdk-contract and integration suites, and opens a GitHub
   issue titled with the failing dependency and version.
4. Dependabot or Renovate is configured for `pyproject.toml` and
   `github-actions`.
5. Lock-refresh pull requests cannot merge unless the integration job is green.

Files: `tests/unit/test_sdk_contract.py`, `tests/golden/catalog_verbs.json`,
`.github/workflows/{ci,nightly}.yml`, `.github/dependabot.yml`.

## Risks

- **Token Factory endpoint paths are unknown to this project.** Nothing in the
  repository references Token Factory. Every path must be confirmed against a
  live tenant and dated in `docs/token-factory-api.md`. A guessed path that
  404s in a user's hands is worse than a tool that says the surface is
  unconfirmed.
- **Integration tests need a funded Nebius tenant and a Token Factory key.**
  That is an organizational dependency, not a code one. If secrets are not
  available, T1 still lands and the job skips; do not fake it with mocks and
  call it integration.
- **T7 touches 46 call sites across every tool module.** It will conflict with
  anything else in flight. Sequence it after T2 so the live smoke suite can
  catch a mistake, and land it as one pull request rather than per-module.
- **Two credential planes double the credential-leak surface.** T3 acceptance
  item 5 adds the key pattern to `sanitize.redact`; do not defer it.
- **Model output entering agent context is a new injection channel.** T5
  acceptance item 2 is not optional.
- **The rate budget can make a legitimate bulk read feel broken.** Report
  `throttled_ms` so the cause is visible rather than mysterious.

## Definition of done

- `pytest tests/integration` passes against a live tenant in the scheduled CI
  job, covering both the IAM plane and the Token Factory plane.
- `tokenfactory_chat_completion` returns text from a real model, and
  `check_environment` reports both credential planes side by side.
- `grep -rn 'await safe(' src/` returns 0.
- The golden verb histogram matches 305 and the `sdk-matrix` job is green at
  both ends of the allowed `nebius` range.
- A `uv lock --upgrade` failure opens a GitHub issue before it reaches a user.
- `docs/token-factory-api.md` records a verification date for every endpoint
  the release ships, and names every endpoint it could not confirm.
- The four quality gates plus `scripts/check_docs.py` are green.
